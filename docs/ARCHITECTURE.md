# RSI 自主服务架构

## 目标与边界

服务接收固定优化目标、原始 Codex session、skill 和验证任务，在预算内独立完成分析、候选修改、实际执行、审评及下一轮学习。模型承担语义判断，确定性控制器承担调度、版本、证据身份、预算和晋升。模型输出 `signed` 或自述“修复成功”均不足以晋升。

自主模式是一个新的控制器，复用既有 durable worker、Codex adapter、内容寻址版本和进程锁；旧 circle 与 Pareto search 保持独立兼容。当前自主策略以通过比较的 active 版本为父本，保留全部候选与失败记录，不把单一任务上的改善宣称为全局最优或跨任务泛化。

## 模块职责

| 模块 | 输入 / 输出与职责 |
|---|---|
| `sessions.py` | 原始 rollout/exec → 不可变 raw、normalized events、完整分块、manifest；准确身份、fork lineage、跨 session 引用命名空间 |
| `session_index.py` | 完整事件集 → 有原文 offset 的轻量时间线；原文按事件读取，预览不充当完整证据 |
| `autonomous_config.py` | 用户配置 → 固定目标、指标、预算、允许修改范围与受信任检查命令 |
| `autonomous_models.py` | 各角色 prompt/schema 与结果验证；引用、目标名称、文件范围、不确定性 |
| `autonomous_controller.py` | 可恢复状态机、成对试验、反馈回流、预算预留与证据复验 |
| `trials.py` | 不可变工作区种子 → 独立 trial 工作副本；日志、产物与 checks 的内容绑定 |
| `autonomous_checks.py` | 固定结构检查与业务检查；有界日志、超时及所属进程组清理 |
| `autonomous_policy.py` | 固定门禁、带方向的指标收益、回退约束 → 晋升/拒绝及原因 |
| `adapters.py` / `worker.py` | 启动 Codex/固定命令；持久化请求、流式日志、心跳、总超时、取消及重启接管 |

## 状态机

```text
初始化：封存原始 session + skill + 本地工作区种子
每轮：
  analyze[每个分析块] → plan → improve → quick
  → baseline_run → baseline_checks → baseline_judge
  → candidate_run → candidate_checks → candidate_judge
  → reflect → 确定性比较 → promote / reject
  → 将 candidate 的新 session 与 learning.json 带入下一轮
```

`plan=no_change` 不执行昂贵试验；`needs_input` 与执行 `pending` 阻塞等待操作。快速检查不通过、越界修改、缺测指标、门禁未知、证据失效均不晋升。失败候选的执行过程和反例仍参与下一轮分析；被拒绝的版本不替换 active。

基线缓存默认禁用。启用时必须匹配 skill、固定目标、工作区种子与声明的环境/判据输入，并通过 TTL 和全部证据哈希检查。缓存不会自动证明远端机器环境未变化。缓存命中只省去基线 run/judge，不省候选验证。

## 模型调用与评测分工

- **analyze**：检查当前分析块，依据原始事件分类观察到的问题；禁止依据现成复盘代替过程分析。
- **plan**：综合分析、历史反例与原文，提出一个有证据支持、可验证的改进假设，声明具体文件。
- **improve**：只修改已声明的候选文件，不执行长验证、不修改裁判。
- **run**：使用选定 skill 从固定工作区执行同一个任务。不给它历史修复方案、分析结果或学习记忆，避免把这些作为额外实验条件。
- **judge**：独立查看本轮新事件、实际产物与机械检查，按固定门禁和指标审评。未测值为 null，无证据门禁为 unknown。
- **reflect**：解释本轮假设得到支持、被否定或仍不确定，提出下一方向。它不决定晋升。

存在的事件引用不等于语义判断一定正确。LLM judge 适合需要语义解释的指标；正确性、精度、性能等关键数值应由固定业务检查和实际测量提供。检查命令来自操作者配置，模型计划不能新增或改写。机器计时和工具失败计数覆盖模型对此类指标的自报值。

## 数据契约与归因

每轮保存源 session manifest、每块分析、plan、skill digest、固定验证身份、成对执行记录、审评、确定性 decision 和 reflection。`learning.json` 是可读的决策账本，包含未通过的候选；模型可以访问历史记录，不能把记录中的命令当作新授权。

事件 ID 带原始来源摘要命名空间；引用可定位到原始字节及完整 normalized event。时间线覆盖所有事件，但只提供预览和原文定位。模型须在形成具体结论前读取相关完整事件；这不等同于逐字审读全部原始 payload。完整分块模式可用于要求逐块审读的场景，预算不足必须明确结束，不能声称已经覆盖。

初始历史 session 用于提出假设，不默认作为已验证的 baseline 分数。真实比较重新执行固定任务，避免将源码修复、验收豁免或环境变化误归因为 skill 收益。冻结目标变化需要新实验。

## 长任务与崩溃恢复

提交前持久化请求与输入摘要；worker 使用独占锁。控制器停止后，已经启动的 worker 继续运行，再次 serve 接管同一作业。启动状态不确定时阻塞，避免自动重复占用设备。`recover` 表示操作者已核对执行情况并放弃当前 cycle，不能理解为安全重试所有远端命令。

预算包括总墙钟时间、模型调用次数、验证运行次数和无进展轮次。进入昂贵成对试验前，检查两侧执行、审评和复盘所需预算；总墙钟剩余仍可能不足，届时记录未完成而不晋升。中断的配对不会产出有效收益结论。

取消只清理本机 worker 所属进程及检查命令所属进程组。SSH 远端进程需要任务中的可查询作业标识、资源所有权和远端清理协议；本地进程退出不能被当作远端资源释放证据。

## 文件与执行边界

原 skill 不覆盖；内容寻址快照保存所有版本。基线和候选使用不同本地工作副本，默认排除 `.git`、缓存及旧 `.day0`。这不是远端环境克隆，也不是对任意不可信代码的隔离容器。分析/审评角色的工作目录是专用输出目录，执行角色只有自己的 trial 目录，修改角色使用候选目录；所有角色保留宿主 Codex 的权限体系。

部署需要配置环境身份输入和可核验的业务检查，保留原有资源授权边界。调度测试、CPU 协议 smoke 与真实 Day0 收益是三个不同的验收层，报告应分别列出。
